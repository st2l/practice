# stack-shellcode (CTF task)

## 1) Небольшое описание уязвимости и почему она возникает

Уязвимость типа `stack buffer overflow`: функция читает больше данных, чем размер локального буфера.

```c
char note[96];
read(0, note, 300);
```

Переполнение позволяет перезаписать адрес возврата.

## 2) Способы защиты от уязвимости

- Ограничивать чтение размером буфера.
- Не делать стек исполнимым (без `-z execstack`).
- Включать canary/PIE/RELRO/NX.
- Валидировать ввод и тестировать бинарь на переполнения.

## 3) Как запускать приложение (с командами)

```bash
cd stack-shellcode
docker compose up --build -d
```

Проверка сервиса:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd stack-shellcode
docker compose down
```

Флаг задаётся через `docker-compose.yml` переменной окружения `FLAG`.

## 4) Описание уязвимости в реализованном приложении

Приложение дополнительно печатает адрес буфера (`Clipboard address`), что даёт утечку стека. При исполнимом стеке это позволяет положить shellcode в буфер и передать управление на него через BOF.

## 5) PoC-эксплоит для получения флага

PoC: `solve.py`.

```bash
cd stack-shellcode
python3 solve.py REMOTE
```

После получения shell:

```bash
cat flag.txt
```
