# tcache-poisoning (CTF task)

## 1) Небольшое описание уязвимости и почему она возникает

Задача сочетает несколько heap-ошибок:

- Утечка libc через неочищенную память после возврата чанка из `unsorted bin` (видны `fd`/`bk` `main_arena`).
- `double-free` и `use-after-free` из-за повторного освобождения одного и того же указателя.

Причина - отсутствие корректного управления жизненным циклом heap-объектов и проверок повторного `free`.

## 2) Способы защиты от уязвимости

- После `free` обнулять указатели и состояния слотов.
- Запрещать повторное освобождение одной записи.
- Очищать память перед повторной выдачей пользователю.
- Добавлять валидацию индексов/состояния и использовать sanitizers при тестировании.

## 3) Как запускать приложение (с командами)

```bash
cd tcache-poisoning
docker compose up --build -d
```

Проверка сервиса:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd tcache-poisoning
docker compose down
```

Флаг задаётся через `docker-compose.yml` переменной окружения `FLAG`.

## 4) Описание уязвимости в реализованном приложении

В менеджере заметок можно получить libc leak через `unsorted bin`, затем сделать `double-free` малого чанка и через UAF подменить `fd` (с учетом safe-linking). Это приводит к tcache poisoning и записи адреса `win` в глобальный `speak_fn`, после чего вызов `Speak note` печатает флаг.

## 5) PoC-эксплоит для получения флага

PoC: `solve.py`.

```bash
cd tcache-poisoning
python3 solve.py REMOTE
```

PoC использует локальные `libc.so.6` и `ld-linux-x86-64.so.2`. После успешной эксплуатации флаг выводится приложением.
