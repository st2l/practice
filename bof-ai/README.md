# bof-ai (CTF task)

## 1) Небольшое описание уязвимости и почему она возникает

`Stack buffer overflow` возникает, когда в фиксированный буфер записывается больше данных, чем он вмещает. Причина в отсутствии строгого ограничения длины входа перед записью в стековый массив.

## 2) Способы защиты от уязвимости

- Ограничивать чтение/копирование реальным размером буфера.
- Использовать безопасные функции ввода с лимитами длины.
- Включать hardening: `-fstack-protector-strong`, `-fPIE -pie`, `-Wl,-z,relro,-z,now`, NX/DEP.
- Дополнительно проверять код fuzzing/ASAN/SAST.

## 3) Как запускать приложение (с командами)

```bash
cd bof-ai
make
docker compose up --build -d
```

Проверка сервиса:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd bof-ai
docker compose down
```

Флаг задается в `docker-compose.yml` через `FLAG` (есть дефолт в `entrypoint.sh`).

## 4) Описание уязвимости в реализованном приложении

В приложении есть "AI-фильтр" (`check_bad_payload`), но он построен на blacklist-проверках и не устраняет сам факт переполнения стека. За счет BOF можно изменить выполнение и перейти в `win`, где вызывается `system("cat flag.txt")`.

## 5) PoC-эксплоит для получения флага

Готовый PoC: `solve.py`.

```bash
cd bof-ai
python3 solve.py HOST=127.0.0.1 PORT=1337
```

После успешной эксплуатации выводится содержимое `flag.txt`.
