# bof-ai practice task

Мини-приложение с уязвимостью переполнения буфера (stack buffer overflow) находится в `bof-ai/`.

## Что за уязвимость и почему возникает

`Buffer Overflow` (BOF) — это класс уязвимостей, при котором программа записывает в буфер больше данных, чем он может хранить.

Чаще всего причина — отсутствие корректной проверки длины входа: разработчик выделяет фиксированный массив, но чтение/копирование делает без ограничения по размеру.

Последствия зависят от контекста, но типичный риск для stack-based BOF — перезапись соседних данных на стеке (в том числе служебных), что может привести к аварийному завершению или захвату управления выполнением.

## Как защищаться от этой уязвимости

- Всегда проверять длину входных данных и читать не больше размера буфера.
- Использовать безопасные обертки/функции с ограничением длины.
- Включать компиляторные и рантайм-защиты:
  - stack canary (`-fstack-protector-strong`)
  - PIE/ASLR (`-fPIE -pie`)
  - RELRO (`-Wl,-z,relro,-z,now`)
  - NX/DEP
- Проводить fuzzing и SAST/DAST проверки.

## Как запускать приложение

Из корня репозитория:

```bash
cd bof-ai
make
docker compose up --build -d
```

Сервис будет доступен на `127.0.0.1:1337`.

Проверка подключения:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd bof-ai
docker compose down
```

## Где задается флаг

Флаг задается через `docker-compose`:

`bof-ai/docker-compose.yml`

```yaml
environment:
  - FLAG=practice{myamya}
```

Также есть дефолтное значение в `bof-ai/entrypoint.sh`: `practice{test_flag}`.

## Описание уязвимости именно в этом приложении

- Приложение позиционируется как "AI assistant", который пытается фильтровать "вредные" payload'ы (`check_bad_payload`).
- Фильтрация основана на blacklist-подходе и проверке символов, но сама ошибка переполнения остается.
- За счет переполнения можно изменить состояние стека между вызовами и добраться до функции `win`, которая выполняет:

```c
system("cat flag.txt");
```

## PoC-эксплоит для получения флага

Готовый PoC: `bof-ai/solve.py`

Пример запуска:

```bash
cd bof-ai
python3 solve.py HOST=127.0.0.1 PORT=1337
```

Скрипт отправляет специально подобранные данные и переводит выполнение к печати `flag.txt`.

## Особенности запуска

`Dockerfile` динамически НЕ компилирует бинарный файл из сурсов - он просто копирует готовый из репозитория.

Причиной является необходимость *определенных концовок адресов определенных функций* в бинарном файле.
Это в свою очередь надо для того чтобы обойти *AI firewall*.

Требования при компиляции:
1) функция `main`, функция `win` и asm строка из функции `m` `call    instance` должны обладать **одинаковым вторым с конца байтов в адресе**

> Пример:
```txt
0000000000401362                 call    instance
00000000004013DB                 public win
00000000004013EC                 public main
> 
```

2) asm строка из функции `m` `call    instance` должна располагаться на адресе последний байт которого может быть представлен в
виде корректной английской буквы в таблице ASCII

Только тогда эксплуатация конкретно этой программы возможна.

## Компиляция программы

Скомпилировать можно при помощи команды:
```bash
gcc -O0 -fno-stack-protector -fno-omit-frame-pointer -fno-optimize-sibling-calls -fstack-reuse=none -no-pie -fno-pie main.c -o build/chat_ai -no-pie
```

или при помощи Makefile:
```bash
make
```
