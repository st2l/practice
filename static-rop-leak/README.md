# static-rop-leak (CTF task)

## 1) Небольшое описание уязвимости и почему она возникает

Основа задачи - `stack buffer overflow`: в `Leave a review` можно передать до 512 байт в буфер 128 байт.

```c
char buf[128];
read(0, buf, n); // n до 512
```

Это переписывает стек и позволяет подменить адрес возврата.

## 2) Способы защиты от уязвимости

- Строго ограничивать длину ввода размером буфера.
- Добавлять проверки граничных условий до `read`.
- Включать hardening (stack protector, RELRO, NX) и контроль утечек адресов.
- Не выводить пользователю адресозависимые данные.

## 3) Как запускать приложение (с командами)

```bash
cd static-rop-leak
docker compose up --build -d
```

Проверка сервиса:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd static-rop-leak
docker compose down
```

Флаг задаётся через `docker-compose.yml` переменной окружения `FLAG`.

## 4) Описание уязвимости в реализованном приложении

Помимо BOF, сервис выдает обфусцированный "session token", который раскрывает адрес в `.text` после обратного преобразования. Это позволяет посчитать базу PIE и собрать рабочую ROP-цепочку для вызова `system("/bin/sh")`.

## 5) PoC-эксплоит для получения флага

PoC: `solve.py`.

```bash
cd static-rop-leak
python3 solve.py REMOTE
```

После получения shell:

```bash
cat flag.txt
```
