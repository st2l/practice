# notes_again (CTF task)

## 1) Небольшое описание уязвимости и почему она возникает

Это `stack buffer overflow`: в пункте `Change name` данные читаются без ограничения под размер буфера.

```c
char name[64];
read(0, name, 1000);
```

В результате можно перезаписать стековые данные (включая управление потоком выполнения).

## 2) Способы защиты от уязвимости

- Читать не больше размера буфера (`sizeof(name)-1`) и ставить `NUL`-терминатор.
- Проводить строгую валидацию длины пользовательского ввода.
- Не отключать hardening (canary/PIE/RELRO/NX).
- Добавлять fuzzing/ASAN для проверки опасных участков.

## 3) Как запускать приложение (с командами)

```bash
cd notes_again
docker compose up --build -d
```

Проверка сервиса:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
cd notes_again
docker compose down
```

Флаг передается через `docker-compose.yml` переменной `FLAG`.

## 4) Описание уязвимости в реализованном приложении

Переполнение вызывается при выборе пункта `1) Change name`. Дальше через утечки и ROP можно получить выполнение команд, а флаг лежит в контейнере в `/app/flag.txt`.

## 5) PoC-эксплоит для получения флага

PoC: `solve.py`.

Запуск против docker-сервиса:

```bash
cd notes_again
python3 solve.py REMOTE
```

При необходимости после получения shell:

```bash
cat /app/flag.txt
```
