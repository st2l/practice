# notes_again (CTF task)

Небольшой бинарный сервис "менеджер заметок" с уязвимостью переполнения буфера на стеке.

## 1) Какая уязвимость и почему возникает

В `main.c` в обработчике пункта `1) Change name` есть чтение:

```c
char name[64];
read(0, name, 1000);
```

`read` записывает до 1000 байт в буфер размером 64 байта, что приводит к stack buffer overflow и позволяет перезаписать канарейку/адрес возврата (при наличии утечки и обхода защит).

## 2) Защита от уязвимости

- Ограничивать размер чтения размером буфера (`read(..., sizeof(name)-1)` и ручной `NUL`-терминатор).
- Использовать безопасный ввод и строгую валидацию длины.
- Включать hardening-флаги компиляции и не ослаблять их.
- Покрывать опасные участки fuzzing/ASAN-тестами.

## 3) Как запустить (Docker Compose)

```bash
docker compose up --build -d
```

Сервис слушает порт `1337` (TCP).

Проверка подключения:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
docker compose down
```

## 4) Флаг

Флаг передаётся через `docker-compose.yml` переменной окружения `FLAG`.


## 5) Уязвимость в этой реализации

- Переполнение происходит при выборе пункта `1`.
- Через утечки и ROP можно получить выполнение команд.
- Флаг кладётся в контейнер в `/app/flag.txt` (через `entrypoint.sh`).

## 6) PoC exploit

В репозитории есть эксплоит на pwntools: `solve.py`.

Пример запуска против локального docker-сервиса:

```bash
python3 solve.py REMOTE
```

Если нужно запускать против локального процесса:

```bash
cd bin
python3 solve.py
```

> Примечание

Для работы скрипта и корректной эксплуатации необходимы бинарные файлы Libc и ld.
Получить из контейнера их можно так:

```bash
# 1) Поднять сервис
docker compose up --build -d

# 2) Узнать id контейнера сервиса notes-again
CID=$(docker compose ps -q notes-again)

# 3) Скопировать libc и ld из контейнера в текущую директорию
docker cp "$CID:/app/libc.so.6" ./libc.so.6
docker cp "$CID:/app/ld-linux-x86-64.so.2" ./ld-linux-x86-64.so.2
```

Альтернатива, если контейнер запускать не хочется:

```bash
# Собрать образ и создать временный контейнер
docker compose build
CID=$(docker create $(docker compose images -q notes-again))

# Скопировать нужные файлы
docker cp "$CID:/app/libc.so.6" ./libc.so.6
docker cp "$CID:/app/ld-linux-x86-64.so.2" ./ld-linux-x86-64.so.2

# Удалить временный контейнер
docker rm "$CID"
```

Скрипт автоматически подтянет необходимые файлы. Они требуются для корректно работы оффсетов в ROP chain.


## Использование компилированного файла

В целом, для работы данного задания достаточно компилировать прямо в Docker runtime. Однако мною ввиду удобства был выбран путь простого копирования.

Скомпилировать бинарный файл можно при помощи простой команды:
```bash
gcc -g -O0 main.c -o bin/notes_manager
```

Для удобства сделан Makefile:

```bash
make clean
make
```
