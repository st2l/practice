# notes_again (CTF task)

Небольшой бинарный сервис "менеджер заметок" с уязвимостью переполнения буфера на стеке.

## 1) Какая уязвимость и почему возникает

В `main.c` в обработчике пункта `1) Change name` есть чтение:

```c
char name[64];
read(0, name, 1000);
```

`read` записывает до 1000 байт в буфер размером 64 байта, что приводит к stack buffer overflow и позволяет перезаписать канарейку/адрес возврата (при наличии утечки и обхода защит).

## 2) Защита от уязвимости

- Ограничивать размер чтения размером буфера (`read(..., sizeof(name)-1)` и ручной `NUL`-терминатор).
- Использовать безопасный ввод и строгую валидацию длины.
- Включать hardening-флаги компиляции и не ослаблять их.
- Покрывать опасные участки fuzzing/ASAN-тестами.

## 3) Как запустить (Docker Compose)

```bash
docker compose up --build -d
```

Сервис слушает порт `1337` (TCP).

Проверка подключения:

```bash
nc 127.0.0.1 1337
```

Остановка:

```bash
docker compose down
```

## 4) Флаг

Флаг передаётся через `docker-compose.yml` переменной окружения `FLAG`.


## 5) Уязвимость в этой реализации

- Переполнение происходит при выборе пункта `1`.
- Через утечки и ROP можно получить выполнение команд.
- Флаг кладётся в контейнер в `/app/flag.txt` (через `entrypoint.sh`).

## 6) PoC exploit

В репозитории есть эксплоит на pwntools: `solve.py`.

Пример запуска против локального docker-сервиса:

```bash
python3 solve.py REMOTE
```

Если нужно запускать против локального процесса:

```bash
cd bin
python3 solve.py
```
